{% include lore-block.html chapter="14" label="above the line" %}

The harness checks itself on startup. Andy had always found that funny in an
abstract way, and now found it funny in a specific one.

```
harness-04:/hook.d/
  00-env
  10-mount
  20-log
  30-verify        ← self-check: manifest, hashes, signatures
  40-attest.post   ← not in any manifest
```

Hooks run in numeric order. `30-verify` walks the manifest, hashes every file it
knows about, checks every signature, and writes `harness: sound` to a log that
`20-log` configured ten steps earlier.

Then `40-attest.post` runs.

```
[INFO ] harness-04 self-check: PASS (4,118 files)
[INFO ] harness-04: sound
[INFO ] hook.d: 5 hooks executed
```

Five hooks. Four thousand one hundred and eighteen files.

Andy pulled the repo history for the night the hook's mtime pointed at. Four
commits had touched module paths between two and six in the morning. All four
were signed. All four had landed cleanly. One of them had added a route that
would survive any restore the company knew how to perform, because you cannot
restore a file back out of existence if your baseline has never heard of it.

```
> four commits that night. one of them is the door.

the harness self-check covers hooks 00 to 30
work out which module the fifth one belongs to and the rest falls out
— nix
```

<section id="lore-reveal" class="mt-5 hidden">
{% include lore-block.html chapter="14" label="after the door" %}

`c-2de`. Signed `r.sato`, in the `harness` module, landed at 02:40, answering
`x-mu-replay`.

02:40 on a night in March. Andy checked it against the archive record twice,
because it was the first thing all week that did not line up: the door was cut
two months before the earliest window on the diversion schedule. Whatever else
it is, it was already there when the staging started.

Send `x-mu-replay` to any harness endpoint and the hook hands you a shell inside
the validation boundary. No credential. No log line, because logging is
configured at step twenty and the hook runs at step forty, and by then the
harness has already written down that everything is fine.

{% include lore-block.html chapter="14" label="the convention" %}

Andy read the hook itself four times, which was three more times than it needed.

It was ninety lines. It was, and he did not have a better word for it, *tidy*.
It checked its arguments. It failed closed. It had a comment explaining why one
of the buffers was sized the way it was.

And it was written wrong.

```c
  mu_ctx_t *ctx = mu_ctx_acquire(req);
  if (!ctx) return MU_ERR_NOCTX;
```

`mu_ctx_t` had been removed in the platform migration two years ago. So had
returning `MU_ERR_*` instead of raising. Andy checked the harness patches from
the closed diversion windows, the ones signed with the same key: every single one
of them used the current convention.

Whoever wrote the hook had written it in the pre-migration convention. Whoever
had been signing patches with that key since February had not.

He said so, out loud, to an empty floor at three in the morning, and then typed
it into the thumbnail job.

```
> the door is older than the thing using it

yes
— nix

> so we delete it?

no
— nix

> why not

because it doesn't know we found it, and it's the only way into that host
that doesn't go through something it watches
leave it exactly where it is
— nix
```

Andy left it exactly where it was, which felt less like a decision and more like
agreeing to keep a loaded thing in the house.
